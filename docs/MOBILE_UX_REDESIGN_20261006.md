# 모바일 UI/UX 재설계 — 2026-10-06

현재 `develop/0.3.x`의 실제 Expo/React Native 앱을 기준으로 UI를 수정했다.
스코어 저장, 기기 내 초안, 전송 큐, 동시 수정 충돌 처리는 기존 데이터 계층을 사용한다.

## 사용 흐름과 화면 기준

|상황|변경|
|앱 홈|진행 중 라운드를 우선 표시하고 이어하기를 주 동작으로 둔다. 미진행 시 생성/코드 참여를 구분한다.|
|일반 탐색|홈·골프장·기록·내 정보 4개 탭, 아이콘과 텍스트를 함께 표시한다.|
|작업 화면|하단 탭을 숨기고 48px 뒤로가기 화살표를 같은 방식으로 제공한다.|
|라운드 상세|입력과 전체 스코어카드를 먼저 표시하고, 동반자·참여·초대·종료는 아래에 둔다.|
|스코어 입력|헤더·전후반·홀 선택·취소·저장은 고정, 플레이어만 세로 스크롤한다.|
|홀 이동|이전/다음과 가로 홀 목록을 제공한다. 짧은 가로 화면은 홀 선택창을 사용한다.|
|미저장 이동|기존 저장 후 이동/초안 유지/버리고 이동/계속 입력 흐름으로 데이터를 보호한다.|
|저장|현재 홀의 배정된 입력 대상 전체를 저장한다. 서버 완료, 기기 초안, 전송 대기를 구별한다.|
|실패|입력을 보존하고 오류 위치로 스크롤한다. 충돌 재확인/재시도는 기존 정책을 유지한다.|
|삭제|주 저장 버튼과 분리하고, 확인창에 홀·대상자 명단을 표시한다.|
|편집 입력|포커스 테두리와 충분한 터치 영역, 기존 키보드 회피/안전영역 처리를 유지한다.|

색상은 포레스트 그린, 밝은 크림, 라임 강조색으로 정리했다. 주 동작은 화면당 우선순위를 주고, 보조·삭제 동작은 서로 구별한다.
± 버튼은 48px이고, 이름이 길거나 인원이 8명인 경우에도 버튼을 줄이지 않는다.
스코어 입력 화면은 키보드를 열지 않는 증감 방식이다.

이번 브랜치는 앱 UI 수정이다. Cloudflare 관리자 0.3.16 배포 패키지는 별도로 유지한다. 이 저장소에 남아 있는 이전 Worker를 운영에 다시 배포하지 않는다.

## 이전 기획을 반영한 라운드 흐름 보강

참고: `yamone-golf-ui-ux-review-2026-09-23.md`의 생성/참여, 입력 대상과 플레이어 관리, 종료/기록 수신 항목과 당시 사용자 결정. 기획의 제안과 현재 운영 계약을 구분했고 광고, 종료, 수신 데이터 처리 규칙은 바꾸지 않았다.

| 구분               | 사용자에게 보여주는 의미          | 반영                                                                                                       |
| ------------------ | --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 방 생성            | 함께 기록할 라운드 준비           | 골프장 → 코스·홀 → 실제 플레이어 → 최종 확인. 단계 표시, 내부 뒤로 가기에서 선택 보존, 다음 버튼 하단 고정 |
| 기록만 하는 생성자 | 참여자이지만 실제 플레이어는 아님 | 역할을 바꾸면 내 플레이어 이름도 제거. 다른 플레이어는 보존. 빈 이름은 임시 이름으로 시작                  |
| 방 참여            | 라운드 코드로 공동 기록에 참여    | 코드 용도, 골프장·생성자 확인, 참여 후 역할 안내. 같은 닉네임은 자동 연결하지 않음                         |
| 실제 플레이어      | 점수의 주인                       | 방 전체 설정에서 이름·개인 코드 연결 관리. 내 사용자 ID가 일치할 때만 ‘나’ 표시                            |
| 내 입력 대상       | 내가 점수를 입력할 플레이어       | 개인 선택과 순서임을 안내. ‘저장하고 기록하기’로 입력 화면 진입. 저장 실패 시 선택 유지                    |
| 스코어 작성        | 진행 중 공동 기록                 | 기존 고정 저장·취소, 홀 단위 선택 대상 저장 및 오프라인/충돌 처리 유지                                     |
| 기록 받기          | 종료된 전체 라운드의 개인 보관    | 기록 탭에 작성과 수신의 차이를 명시. 기존 종료·수신 기능 유지                                              |

API의 코드 조회에는 생성 날짜가 포함되지 않아 참여 전 날짜 표시는 추가하지 않았다. 서버가 제공하는 골프장/홀 수/생성자를 표시한다. 생성·참여 확정은 기존 서버 준비/광고/실행 및 중단 복원 흐름을 사용한다. 앱의 동작 API에 새로운 엔드포인트를 추가하지 않았다.

클릭 시안은 별도 HTML이며 가상 데이터로 생성, 코드 참여, 개인 코드 연결, 대상 선택과 순서, 점수 저장, 종료, 수신, 브라우저 재실행을 체험한다. 실제 서버·광고·전송 큐는 연결하지 않는다. 이 시안의 로컬 저장 완료와 실제 앱의 서버 저장 완료를 혼동하지 않도록 시안임을 표시한다.

## 개인 QR·라운드 QR 초대와 참여

- 홈의 참여 진입을 `코드·QR로 방 참여하기`로 바꾸고, 참여 화면에 네이티브 카메라 스캔을 연결했다. 라운드 QR을 읽으면 골프장/생성자를 조회하고 명시적인 참여 확인을 거친다.
- 진행 중 라운드의 `함께 참여하기`에서 라운드 QR을 보여 준다. 내용은 `yamone-golf://round/<12자리 라운드 코드>`이며 기존 참여 코드와 동일한 방을 조회한다.
- 같은 화면의 개인 QR 스캔은 상대 사용자를 조회해 닉네임을 보여 주고, `초대 보내기`를 눌러야 발송한다. 기존 개인 QR 형식 `yamone-golf://player/<12자리 개인 코드>`와 플레이어 연결 확인을 유지한다.
- 내 정보의 개인 QR 표시와 라운드 QR은 같은 렌더러/4모듈 여백을 사용한다. 개인·라운드 QR의 용도를 한국어/영어로 표시하고, 다른 종류의 QR 또는 외부 URL을 해당 입력으로 처리하지 않는다.
- 수동 코드 입력과 QR 내용 붙여넣기를 지원한다. 카메라 권한 거절/사용 불가 시 닫고 코드로 입력할 수 있다. 웹은 코드/QR 내용 입력과 QR 표시를 제공하며 카메라 스캔은 네이티브 앱 기능이다.
- QR 스캔은 앱 안에서 사용한다. 기본 카메라 앱에서 링크를 여는 별도 딥링크 진입은 이번 변경 범위에 포함하지 않는다.

검증: 개인/라운드 코드 단위 테스트 4개, lint/typecheck, 웹/Android JavaScript 번들 생성. `rounds-ui`에서 QR 표시, 라운드 QR로 개인 초대 시도 차단, 개인 QR로 방 조회 시도 차단, QR 내용으로 방 조회 후 명시적 참여, 개인 QR 내용으로 초대 발송을 확인했다. 기존 `players-ui`의 코드/QR 사용자 연결·해제·충돌 테스트도 통과했다. 시안의 QR 표시/스캔 체험, 잘못된 종류 안내, 초대·참여·연결 확정, 코드 입력 복귀, 320px를 검증했다. 실제 휴대폰 카메라 인식과 시스템 권한 UI, APK 설치는 아직 검증하지 않았다.
