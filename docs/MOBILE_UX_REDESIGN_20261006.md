# 모바일 UI/UX 재설계 — 2026-10-06

현재 `develop/0.3.x`의 실제 Expo/React Native 앱을 기준으로 UI를 수정했다.
스코어 저장, 기기 내 초안, 전송 큐, 동시 수정 충돌 처리는 기존 데이터 계층을 사용한다.

## 사용 흐름과 화면 기준

|상황|변경|
|앱 홈|진행 중 라운드를 우선 표시하고 이어하기를 주 동작으로 둔다. 미진행 시 생성/코드 참여를 구분한다.|
|일반 탐색|홈·골프장·기록·내 정보 4개 탭, 아이콘과 텍스트를 함께 표시한다.|
|작업 화면|하단 탭을 숨기고 48px 뒤로가기 화살표를 같은 방식으로 제공한다.|
|라운드 상세|입력과 전체 스코어카드를 먼저 표시하고, 동반자·참여·초대·종료는 아래에 둔다.|
|스코어 입력|헤더·전후반·홀 선택·취소·저장은 고정, 플레이어만 세로 스크롤한다.|
|홀 이동|이전/다음과 가로 홀 목록을 제공한다. 짧은 가로 화면은 홀 선택창을 사용한다.|
|미저장 이동|기존 저장 후 이동/초안 유지/버리고 이동/계속 입력 흐름으로 데이터를 보호한다.|
|저장|현재 홀의 배정된 입력 대상 전체를 저장한다. 서버 완료, 기기 초안, 전송 대기를 구별한다.|
|실패|입력을 보존하고 오류 위치로 스크롤한다. 충돌 재확인/재시도는 기존 정책을 유지한다.|
|삭제|주 저장 버튼과 분리하고, 확인창에 홀·대상자 명단을 표시한다.|
|편집 입력|포커스 테두리와 충분한 터치 영역, 기존 키보드 회피/안전영역 처리를 유지한다.|

색상은 포레스트 그린, 밝은 크림, 라임 강조색으로 정리했다. 주 동작은 화면당 우선순위를 주고, 보조·삭제 동작은 서로 구별한다.
± 버튼은 48px이고, 이름이 길거나 인원이 8명인 경우에도 버튼을 줄이지 않는다.
스코어 입력 화면은 키보드를 열지 않는 증감 방식이다.

## 검증

- `npm run lint`, `npm run typecheck`, `npm test` 통과.
- `tests/scores-ui.ts`: 기존 저장 상태/미저장 이동/동시 수정 충돌/실패 재시도/삭제/영어320px 검증 통과.
- `tests/mobile-redesign-ui.ts`: 실제 로컬 Worker/D1로 8명 저장, 스크롤 중 저장 버튼 고정, 320/390/430px 및 짧은 가로 화면, 골프장/프로필/스코어카드 검증.
- 웹 및 Android JavaScript 번들 생성 확인. APK 설치, 실기기 시스템 제스처/키보드/화면읽기 검증은 별도로 필요하다.

```bash
npm ci
npm run export:web
npm run test:ui -- tests/mobile-redesign-ui.ts tests/scores-ui.ts
```

로컬에서 눌러 보기: `npm run db:local` 후 한 터미널에서 `npm run server`, 다른 터미널에서 `npm run preview`를 실행해 http://localhost:4173 에 접속한다. 로컬 개발 데이터만 사용한다.

이번 브랜치는 앱 UI 수정이다. Cloudflare 관리자 0.3.16 배포 패키지는 별도로 유지한다. 이 저장소에 남아 있는 이전 Worker를 운영에 다시 배포하지 않는다.
