# 5단계 서버·복구·운영 점검 — 2026-10-27

개발·로컬 검증 결과다. Cloudflare CLI 미인증 상태를 다시 확인했고 운영 D1 읽기도 인증 단계에서 실패했다. 운영 스키마·이력·secret 등록 상태·실제 수집 상태를 확인하거나 운영 DB/배포를 변경한 결과가 아니다.

## DB 사전 점검

저장소 루트에서 다음 명령을 사용한다. 원격 모드는 기존 `env.production`의 `DB`와 `yamone-golf`만 사용하며, 기본 개발 DB나 새 DB로 대체하지 않는다.

```bash
npm run db:preflight -- --remote --out .tmp/operations/production-20261027.json
```

`scripts/db-preflight.ts`는 고정된 메타데이터 SELECT와 읽기 전용 PRAGMA만 실행한다. 테이블·열·외래키·인덱스·트리거 정의를 신규 DB의 0001~0012와 비교하고, `d1_migrations`의 이름과 국가 설정·수집 위치·상태·지역 매핑 건수를 함께 기록한다. 사용자·점수·이메일 주소·코드·토큰 행을 가져오지 않는다. DB에서 반환한 SQL 문자열을 로컬에서 실행하지 않는다.

미기록 마이그레이션은 수동 반영 여부를 검토할 항목이다. 예를 들어 0010의 필드가 이미 존재하지만 적용 이력에 없는 경우, 중복 ALTER를 실행하지 않고 이력 누락으로 분류한다. 원격 이력은 이름만 있으므로 과거 실행 SQL의 체크섬을 증명하지 못한다. 보고서에는 현재 파일의 SHA-256을 포함하지만 과거 파일과 같다는 뜻은 아니다. 지역 매핑 건수가 같아도 값이 같다는 뜻은 아니다.

스키마 읽기는 여러 요청으로 나뉜다. 스키마 변경을 잠시 멈춘 상태에서 실행하고 실제 작업 직전에 다시 확인한다. 정의가 조금 다르면 동등성을 추정해 통과시키지 않고 검토 항목으로 남긴다. `schema_and_history_match=true`도 배포 승인이나 데이터 동등성 확인이 아니며 `automatic_apply_allowed`는 항상 false다.

종료 코드는 일치 0, 검토 항목 존재 2, 인증/조회/파일 오류 1이다. 일부 조회가 실패하면 성공 보고서를 저장하지 않는다. 기존 보고서는 덮어쓰지 않으므로 재실행 때는 새 파일명을 쓴다. 출력 파일 권한은 0600이며 Git에서 제외된 `.tmp/operations/`를 사용한다.

기존 SQLite 복사본도 수정 없이 검사할 수 있다.

```bash
npm run db:preflight -- --sqlite /absolute/path/to/copy.sqlite --out .tmp/operations/local-copy.json
```

## 복구와 자동 종료

- 운영 `EMAIL_MODE=mock`이나 잘못된 모드는 503으로 차단한다. 이전에는 운영 mock도 실제 발송 없이 성공 상태를 만들 수 있었다. 이제 운영은 필요한 Resend 설정을 갖춘 경우만 이메일 기능을 제공한다. 상태 API는 구성 실패를 `configured=false`로 표시한다.
- 만료된 이메일 인증/복구는 주소를 연결하거나 기존 기기를 폐기하지 않는다. 복구 실패 때 사용자 데이터·복구 키·활성 기기를 유지하며, 성공한 코드로 두 번째 새 기기를 활성화하지 못한다. 원래 성공 요청의 응답 유실 재확인은 유지한다.
- 기존 6시간 무갱신 종료, 종료 시각 고정, 권한·점수/참여 경합, active round 해제와 기기 이전 원자성 검사를 다시 실행했다. 운영 Cron의 실제 실행 이력은 인증 후 별도 확인한다.
- 실제 메일을 보내거나 Resend를 호출하지 않았다. 실기기의 메일 앱 링크·기기 이전·강제 종료는 설치 QA에 남아 있다.

## 백업·복원

로컬 격리 D1에 0001~0012를 적용하고 검증용 사용자·PAR 3~7 골프장·일시 정지된 수집 위치를 넣었다. 실제 Wrangler SQL export를 별도 로컬 DB에 import한 뒤 사용자/골프장/PAR·수집 위치·적용 이력과 외래키 무결성을 대조했다. Node SQLite backup으로도 같은 복원 보존을 자동 검사한다. 운영 데이터나 운영 Time Travel 복원을 실행한 것이 아니다.

Wrangler 4.136.3의 로컬 `d1 export`는 `--persist-to`를 받지 않는다. 이번 격리 검증에서는 임시 설정의 기본 로컬 저장 경로를 검증 DB에 연결해 export했다. 운영 export에는 `--remote --env production`과 기존 DB를 명시한다. 구체적인 인증·bookmark·export·복원 전 확인 순서는 [CLOUDFLARE.md](CLOUDFLARE.md)를 따른다.

1. Cloudflare 인증 후 사전 점검 보고서, 운영 Worker 설정·secret 이름과 실제 Cron 로그를 읽는다.
