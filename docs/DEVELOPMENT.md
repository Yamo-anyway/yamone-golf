# 단계별 진행

## 완료: 1단계 v0.3.0

기존 v0.2.0을 보존하고 Cloudflare 서버·새 앱의 사용자 생성, 기기 인증, 개인 코드/QR, 복구 키, 한국어/영어 기반을 구현했습니다.

## 완료: 2단계 v0.3.1

골프장 검색/등록/공용 정보 수정, 내 골프장 추가/제거/정렬, 라운드 준비/생성, 코드 참여, 개인 코드 초대와 홈 초대 카드를 연결했습니다. 실제 플레이어 슬롯의 초기 생성까지만 포함하며, 연결·해제·입력 대상 관리는 다음 단계입니다.

동시 요청의 진행 중 라운드 1개 제한, 참여 권한 검사, 골프장 버전 충돌, 생성 시 코스/PAR 복사본, 광고 처리와 실제 실행의 분리, 앱 재실행/응답 유실 시 동일 작업 재시도를 서버와 앱에서 처리합니다.

## 완료: 3단계 v0.3.2

플레이어 추가, 임시 이름 수정, 개인 코드/QR 연결과 해제, 삭제 영향 확인, 개인별 입력 대상 선택/해제/정렬/저장까지 연결했습니다. 닉네임은 식별에 쓰지 않으며 확인 화면에 개인 코드를 함께 표시합니다.

서버가 슬롯 버전, 대상 목록 버전, 라운드의 플레이어 목록 버전을 검사합니다. 실제 쓰기 시 활성 기기와 참여 권한을 다시 검사하며, 요청 ID별 중복 실행을 막습니다. 연결·이름·삭제 변경 이력을 남기고 삭제는 슬롯 식별자를 보존하는 방식으로 처리합니다.

진행 중인 라운드의 참여자는 플레이어를 관리합니다. 3단계에서는 종료된 라운드의 미등록 이름 수정만 허용했으며, 아래 7단계에서 종료 후 연결/해제와 수신을 추가했습니다. 개인 입력 목록 변경은 공동 라운드의 마지막 기록 갱신 시각을 연장하지 않습니다.

QR 스캔은 native 앱에 구현했습니다. 브라우저에서는 코드/QR 텍스트를 검증했고 Android 코드 번들도 확인했습니다. 실기기 권한·인식률·백그라운드 복귀는 별도 검증이 남아 있습니다. 실제 카메라·마이크 녹화 또는 사진 저장 기능은 사용하지 않습니다.

미포함: 실제 Cloudflare 리소스 생성/배포, 원격 Git push, APK·iOS 설치 빌드, 실제 광고 SDK·배너, 이메일, 기존 DB 이전. 종료·자동 종료는 아래 6단계에서 연결했습니다.

## 완료: 4단계 v0.3.3

선택 대상 전체의 홀별 저장·수정·삭제, null 미입력, 원자적 버전 비교/재확인, 같은 요청 재시도, 변경 이력을 추가했습니다. 작성 중 갱신과 이동에서 초안을 보호하며 마지막 홀 위치를 사용자·라운드별로 저장합니다. 누적/홀별 순위, 공동 순위, 전반/후반 9홀+합계, 스코어 기호도 연결했습니다.

화면 진입·복귀·홀 이동·명시적 새로고침에서 조회합니다. 지속 polling이나 WebSocket은 없습니다. 진행 중 공동 입력 API는 종료 후 쓰기를 거절합니다. 종료 후 본인 수정은 아래 8단계의 별도 API로 연결했습니다.

## 완료: 5단계 v0.3.4

점수 변경을 기기에 먼저 저장하고 홀별 초안/전송 요청/충돌/보류 상태를 유지합니다. 사용자별 저장소에서 라운드 캐시와 마지막 홀을 복원하며 홈에 보관한 라운드 진입점을 제공합니다. 서버 전송은 원래 user_id에 묶으며 기기 이동·권한 변경을 서버에서 다시 검사합니다.

통신 장애, 응답 유실, 서버 성공 후 로컬 확인 저장 실패에서 같은 요청 ID를 재사용합니다. 연결/전면 복귀 시 재전송하며 지속적인 점수 조회는 하지 않습니다. 초안은 사용자가 저장을 누르기 전까지 서버로 보내지 않습니다. 충돌은 해당 홀만 보류하고 다른 홀 전송은 계속합니다.

서버가 종료 상태를 알려 주면 신규 입력을 막고 미반영 요청을 보관합니다. **종료 후 늦게 도착한 오프라인 점수의 수용 기준은 여전히 미확정**이며 임의 유예 시간이나 강제 덮어쓰기를 추가하지 않았습니다. 자세한 저장·복귀 규칙은 OFFLINE.md에 있습니다.

## 완료: 6단계 v0.3.5

생성자/위임 참여자의 종료, 생성자만 권한 부여·회수, 모든 홀의 초안·전송·충돌 확인, 영속 종료 요청과 앱 재실행 복구를 연결했습니다. 종료 확인은 점수·플레이어·참여자 변경 버전과 실제 쓰기 시 권한을 검사합니다.

서버 Cron과 요청 시점의 만료 검사를 함께 사용합니다. 종료는 기록 변경 +6시간을 기준으로 하며 각 플레이어의 완료 상태는 별도로 보존합니다. 종료 트랜잭션에서 참여자 활성 라운드 제한 해제와 대기 초대 취소까지 처리합니다. 홈에 최근 종료 라운드 진입점을 추가했습니다.

이메일, 실제 광고 SDK/배너, 외부 배포는 수행하지 않았습니다. 늦은 오프라인 점수 수용 정책과 나가기 정책을 임의로 추가하지 않았습니다. 상세 설계는 ENDING.md입니다.

## 완료: 7단계 v0.3.6

종료 후 개인 코드/QR 연결·해제, 보내기/받기/취소 이력, 개인 기록 삭제와 전체 라운드 열람을 연결했습니다. 수신과 활성 라운드 참여를 분리하여 다른 진행 중 라운드가 있어도 종료 기록을 받을 수 있습니다.

기존 참여자는 라운드 광고 이력을 재사용하고 미참여 수신자만 최초 광고를 처리합니다. 수신 요청과 광고 결과를 영속 보관하며 앱 종료/응답 유실 후 같은 요청으로 확인합니다. 이미 삭제한 RECEIPT는 과거 요청 재시도로 복원하지 않습니다. 새로운 DELIVERY만 새 수신 대상으로 표시합니다.

기록 목록은 20개씩 추가 조회합니다. 신페리오는 아직 빈 이력이며 계산 결과를 임의로 생성하지 않습니다. 기본 개인 기록 목록/전체 열람은 수신 기능에 포함했고, 8단계에서 개인 기록 검색·통계·본인 수정을 확장합니다.

## 완료: 8단계 v0.3.7

골프장명 검색, 전체/통계 대상/미완료/9홀 필터, 본인 점수 요약과 개인 통계를 추가했습니다. 통계는 받은 기록 중 현재 본인과 연결된 18홀 완주만 사용하며 평균·최저·최고 타수, PAR 대비 평균, 스코어 분포, PAR별 평균과 최근 10라운드를 제공합니다.

수신자만 현재 본인 슬롯의 점수를 종료 시각+24시간 전에 수정합니다. 서버가 쓰기 트랜잭션에서 기기·수신·연결·기한·점수 버전을 검사합니다. 새로운 수정은 기한 이후 차단하되 이미 성공한 요청의 재확인은 허용합니다. 원본 점수와 개인 통계는 함께 갱신되고 종료 시각과 종료 당시 완료 Snapshot은 유지합니다.

수정 초안과 결과 미확정 요청을 별도로 영속 보관합니다. 홀 이동/화면 이동 확인, 다중 홀 초안 복원, 같은 요청 재시도, 충돌 재확인과 최신 점수 적용, 홈의 수정 이어서 진입점을 제공합니다. 진행 중 오프라인 요청을 자동으로 종료 후 수정으로 전환하지 않습니다. 상세 기준은 PERSONAL_RECORDS.md입니다.

## 완료: 9단계 준비 v0.3.8

신페리오 이력 테이블, 공개 응답 타입, 종료 라운드의 참여자/현재 수신자 조회 API, 받은 기록의 이력 연결을 추가했습니다. 라운드별 순번 1~3의 중복을 차단하며 최신 순으로 반환합니다. 숨김 홀·내부 요청 정보를 공개 SQL에서 제외하고 저장 JSON의 중첩 필드도 명시적으로 선별합니다.

위 준비 단계 이후 사용자의 ‘다음’ 지시에 따라 제안한 두 정책으로 실행 연결을 진행했습니다.

## 완료: 9단계 v0.3.9

종료 후 3시간, 생성자/종료 권한 위임자의 실행 기준으로 최초 계산과 재계산을 연결했습니다. 서버 난수 추첨, 미완료 제외 확인, 재계산 경고, 원본/이력 변경 재확인, 쓰기 시 권한·기한 재검사, 최대 3개와 요청 중복 방지를 포함합니다.

계산 화면은 최신 결과·이전 결과·당시 전체 점수·계산자/시각·제외 명단을 제공합니다. 원본 점수가 바뀌어도 결과는 보존하며 변경 안내를 표시합니다. 실행 요청은 사용자별 기기 저장소에 보관하고 응답 유실/재실행 뒤 동일 요청으로 복구합니다. 다른 진행 중 라운드의 기록과 입력 순서에 영향을 주지 않습니다.

계산 방식은 PAR72/숨김12홀(PAR48)/더블파/핸디캡0~36으로 버전을 고정했습니다. 전·후반에서 각 PAR24의 6홀을 선택할 수 없는 코스는 계산하지 않습니다. 공식 핸디캡 인덱스나 개인 통계가 아닌 해당 라운드 경기 결과입니다. 자세한 수식과 제한은 PEORIA.md에 있습니다.

## 이번 작업: 10단계 개발 연결 v0.3.10-stage10a

Google Mobile Ads SDK 17.1.0을 Expo 설치 방식으로 추가했습니다. 네이티브 TestIds 전면 광고, UMP 선행 확인, 개인정보 선택 재진입, 개발용 앱 ID 환경 분리, Expo Go 차단, 웹 모의 제공자 분리를 구현했습니다.

SDK loaded/opened/closed/error 이벤트를 순서대로 처리하고 로딩 타이머는 show 호출 전에 제거합니다. 초기화 취소·로딩 중 백그라운드·화면 이탈은 완료로 인정하지 않습니다. 네이티브 광고가 React Activity를 일시 중단하는 것은 강제 종료로 오인하지 않습니다. 앱이 죽으면 terminal event가 저장되지 않아 재실행 후 다시 광고가 필요합니다. terminal 결과 저장 후에는 foreground 복귀와 최신 서버 검사 뒤 기능을 실행합니다.

참여 광고 도중 라운드가 끝나거나 초대가 바뀌어도 광고 이력을 먼저 보관합니다. 실제 참여 권한은 execute가 별도로 검사합니다. 광고 처리된 생성 요청을 취소/이동할 때도 기존 요청을 보존해 응답 유실 이후 다른 라운드를 중복 생성하지 않도록 했습니다.

배너는 Shell의 스크롤 밖, 탭 위에 배치하며 활성 화면에서만 마운트합니다. 홈/기록 목록/통계와 서버 조회가 확인된 개인 기록 상세·record 진입 신페리오 열람만 허용합니다. round 경로·생성 준비·초대/참여·입력/수정/종료에는 마운트하지 않습니다. 실패·타임아웃·서버 광고 미설정 시 높이 0/제거입니다.

운영 서버는 개발 모의 결과와 admob-test 결과를 모두 계속 거절합니다. SDK의 일반 전면 광고 닫힘 이벤트는 서명된 서버 검증 증빙이 아닙니다. 이를 신뢰 증빙으로 승격하는 보안 완화는 하지 않았습니다. 운영 승인 경로와 운영 ID/UMP 설정 및 실기기 QA가 완료되기 전 **10단계 전체·출시 완료가 아닙니다**. ADS.md 참조.

## 완료: 11단계 로컬 구현 v0.3.11-stage11a

Resend 전송 어댑터와 D1 `0008_email_recovery.sql`, 활성 기기의 복구 이메일 인증, 15분 1회용 코드, 새 기기의 이메일 복구, 기존 활성 기기 폐기와 복구 키 교체를 구현했습니다. 앱의 수동 코드 입력과 `yamone-golf:///email-recovery` 링크 확인 화면을 연결했습니다.

요청 ID·새 기기 비밀값·다음 복구 키를 요청 전에 SecureStore에 보관하고 응답 유실 재시도에서 그대로 사용합니다. 알 수 없는 이메일과 전송 장애는 같은 공개 응답을 사용하며 코드 원문은 D1에 저장하지 않습니다. 일반 이메일 로그인은 추가하지 않았습니다.

Miniflare mock과 브라우저 UI에서 이메일 인증, 주소 마스킹, 잘못된 코드의 기존 기기 보존, 새 기기 이전, 응답 유실 재시도, 기존 기기 차단을 확인했습니다. 실제 Resend 발송, Android 앱 링크 복귀, 실기기 이전, 운영 마이그레이션·배포는 아직 완료가 아닙니다.
