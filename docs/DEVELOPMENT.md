# 단계별 진행

## 완료: 1단계 v0.3.0

기존 v0.2.0을 보존하고 Cloudflare 서버·새 앱의 사용자 생성, 기기 인증, 개인 코드/QR, 복구 키, 한국어/영어 기반을 구현했습니다.

## 완료: 2단계 v0.3.1

골프장 검색/등록/공용 정보 수정, 내 골프장 추가/제거/정렬, 라운드 준비/생성, 코드 참여, 개인 코드 초대와 홈 초대 카드를 연결했습니다. 실제 플레이어 슬롯의 초기 생성까지만 포함하며, 연결·해제·입력 대상 관리는 다음 단계입니다.

동시 요청의 진행 중 라운드 1개 제한, 참여 권한 검사, 골프장 버전 충돌, 생성 시 코스/PAR 복사본, 광고 처리와 실제 실행의 분리, 앱 재실행/응답 유실 시 동일 작업 재시도를 서버와 앱에서 처리합니다.

## 완료: 3단계 v0.3.2

플레이어 추가, 임시 이름 수정, 개인 코드/QR 연결과 해제, 삭제 영향 확인, 개인별 입력 대상 선택/해제/정렬/저장까지 연결했습니다. 닉네임은 식별에 쓰지 않으며 확인 화면에 개인 코드를 함께 표시합니다.

서버가 슬롯 버전, 대상 목록 버전, 라운드의 플레이어 목록 버전을 검사합니다. 실제 쓰기 시 활성 기기와 참여 권한을 다시 검사하며, 요청 ID별 중복 실행을 막습니다. 연결·이름·삭제 변경 이력을 남기고 삭제는 슬롯 식별자를 보존하는 방식으로 처리합니다.

진행 중인 라운드의 참여자는 플레이어를 관리합니다. 종료된 라운드에서는 기존 참여자의 미등록 이름 수정만 허용합니다. 종료 후 연결/수신에 관한 기능은 7단계에서 추가합니다. 개인 입력 목록 변경은 공동 라운드의 마지막 기록 갱신 시각을 연장하지 않습니다.

QR 스캔은 native 앱에 구현했습니다. 브라우저에서는 코드/QR 텍스트를 검증했고 Android 코드 번들도 확인했습니다. 실기기 권한·인식률·백그라운드 복귀는 별도 검증이 남아 있습니다. 실제 카메라·마이크 녹화 또는 사진 저장 기능은 사용하지 않습니다.

미포함: 실제 Cloudflare 리소스 생성/배포, 원격 Git push, APK·iOS 설치 빌드, 실제 광고 SDK·배너, 이메일, 기존 DB 이전. 종료·자동 종료는 아래 6단계에서 연결했습니다.

## 완료: 4단계 v0.3.3

선택 대상 전체의 홀별 저장·수정·삭제, null 미입력, 원자적 버전 비교/재확인, 같은 요청 재시도, 변경 이력을 추가했습니다. 작성 중 갱신과 이동에서 초안을 보호하며 마지막 홀 위치를 사용자·라운드별로 저장합니다. 누적/홀별 순위, 공동 순위, 전반/후반 9홀+합계, 스코어 기호도 연결했습니다.

화면 진입·복귀·홀 이동·명시적 새로고침에서 조회합니다. 지속 polling이나 WebSocket은 없습니다. 아직 종료 후 본인 수정 권한은 연결하지 않았으므로 종료된 라운드의 모든 점수 쓰기는 서버에서 거절합니다.

## 완료: 5단계 v0.3.4

점수 변경을 기기에 먼저 저장하고 홀별 초안/전송 요청/충돌/보류 상태를 유지합니다. 사용자별 저장소에서 라운드 캐시와 마지막 홀을 복원하며 홈에 보관한 라운드 진입점을 제공합니다. 서버 전송은 원래 user_id에 묶으며 기기 이동·권한 변경을 서버에서 다시 검사합니다.

통신 장애, 응답 유실, 서버 성공 후 로컬 확인 저장 실패에서 같은 요청 ID를 재사용합니다. 연결/전면 복귀 시 재전송하며 지속적인 점수 조회는 하지 않습니다. 초안은 사용자가 저장을 누르기 전까지 서버로 보내지 않습니다. 충돌은 해당 홀만 보류하고 다른 홀 전송은 계속합니다.

서버가 종료 상태를 알려 주면 신규 입력을 막고 미반영 요청을 보관합니다. **종료 후 늦게 도착한 오프라인 점수의 수용 기준은 여전히 미확정**이며 임의 유예 시간이나 강제 덮어쓰기를 추가하지 않았습니다. 자세한 저장·복귀 규칙은 OFFLINE.md에 있습니다.

## 이번 작업: 6단계 v0.3.5

생성자/위임 참여자의 종료, 생성자만 권한 부여·회수, 모든 홀의 초안·전송·충돌 확인, 영속 종료 요청과 앱 재실행 복구를 연결했습니다. 종료 확인은 점수·플레이어·참여자 변경 버전과 실제 쓰기 시 권한을 검사합니다.

서버 Cron과 요청 시점의 만료 검사를 함께 사용합니다. 종료는 기록 변경 +6시간을 기준으로 하며 각 플레이어의 완료 상태는 별도로 보존합니다. 종료 트랜잭션에서 참여자 활성 라운드 제한 해제와 대기 초대 취소까지 처리합니다. 홈에 최근 종료 라운드 진입점을 추가했습니다.

이메일, 실제 광고 SDK/배너, 외부 배포는 수행하지 않았습니다. 늦은 오프라인 점수 수용 정책과 나가기 정책을 임의로 추가하지 않았습니다. 상세 설계는 ENDING.md입니다.

이번 단계 광고는 명시적인 개발 테스트 어댑터입니다. `development`/`test`/`ui-test` 환경만 테스트 완료를 받으며, `production` 환경은 `ads_not_configured`로 거절합니다. 라운드별 광고 이력은 실제 라운드 등록과 동일 트랜잭션에서 저장합니다. SDK 연결 시 광고 표시 중에는 타이머로 완료를 추정하지 않고 실제 완료/실패 이벤트와 생명주기를 연결해야 합니다.

최신 광고 기준은 POLICY.md를 사용합니다. 예전 v0.2 문서의 ‘생성/참여/종료/받기 각각 광고’ 및 ‘4초 polling’은 새 구현의 확정 기준이 아닙니다.
