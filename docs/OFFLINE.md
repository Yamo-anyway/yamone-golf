# 오프라인 입력과 복구 — v0.3.4

## 사용자 흐름

1. 연결된 상태에서 점수 화면을 열면 해당 라운드 코스/PAR, 플레이어, 개인 입력 목록, 마지막 서버 점수를 기기에 보관합니다.
2. +/- 변경은 먼저 저장소에 기록한 뒤 화면에 표시합니다. 여러 번 빠르게 눌러도 쓰기를 순서대로 처리합니다. 저장 실패 시 값을 적용한 것처럼 표시하지 않습니다.
3. 다른 홀/화면으로 갈 때 저장하여 전송 대기열에 넣거나, 초안만 보관하거나, 현재 초안을 버리거나, 계속 입력합니다. 이미 저장된 서버 점수를 ‘초안 버리기’로 삭제하지 않습니다.
4. 앱을 다시 열면 같은 사용자·라운드의 마지막 홀, 여러 홀 초안, 대기 요청과 확인 상태를 복구합니다. 홈의 ‘기기에 보관한 라운드’로 다시 들어갈 수 있습니다.
5. 연결 복구, 앱 전면 복귀, 명시적 재시도에서 전송합니다. 서버 충돌 시 최신 값과 제안 값을 확인합니다. ‘나중에 확인’하면 다른 홀을 계속 기록할 수 있습니다.

## 상태 구분

| 상태                    | 의미                                   | 자동 전송                  |
| ----------------------- | -------------------------------------- | -------------------------- |
| 미입력 / PAR 기본값     | 서버 점수 없음, 아직 저장하지 않음     | 없음                       |
| 저장 전 / 기기 초안     | +/- 변경을 기기에 보관                 | 없음                       |
| 기기에 저장 / 전송 대기 | 저장 버튼으로 서버 전송을 요청함       | 연결 복구·전면 복귀·재시도 |
| 충돌 확인               | 다른 최신 값 존재, 해당 홀 전체 미반영 | 사용자 확인 전 중단        |
| 보류                    | 종료·사용자·권한·입력 대상 변화 등     | 자동 승인 없음             |
| 저장됨                  | 서버 성공 및 기기 대기열 정리 완료     | 완료                       |

기기 초안·대기 점수는 공동 스코어카드와 순위에 합산하지 않습니다. 스코어카드는 최근 확인한 서버 기록임을 표시합니다. 전송 대기 홀의 편집은 잠그며, 다른 홀 입력은 가능합니다. 결과를 모르는 요청을 다른 요청으로 교체하거나 취소해 이미 서버에 반영됐을 가능성을 숨기지 않습니다.

## 영속 저장과 재전송

`ymg:score-offline:v1:<user_id>`에 schema, 사용자 ID, 라운드별 서버 캐시, 마지막 홀, 초안과 큐를 하나의 JSON으로 기록합니다. 각 기기 쓰기는 직렬화합니다. 웹은 사용자별 Web Locks 잠금 안에서 최신 저장 내용을 다시 읽고 수정하며 storage 이벤트로 다른 탭을 갱신합니다. 지원하지 않는 비보안 웹 환경은 안전하게 저장 실패로 처리합니다. native는 앱의 단일 저장 컨트롤러와 AsyncStorage를 사용합니다.

민감한 인증 비밀은 여기에 저장하지 않습니다. native 인증은 기존 SecureStore, 웹은 기존 HttpOnly 쿠키를 유지합니다. 오프라인 프로필은 화면 복구용이며 서버 권한을 부여하지 않습니다. 이전 사용자 큐는 새 사용자 명의로 전송되지 않습니다.

서버 전송 전에 요청 ID와 전체 내용을 저장합니다. 성공 뒤에는 같은 로컬 변경에서 최신 서버 캐시를 반영하고 해당 큐 항목을 지웁니다. 서버 성공 후 이 저장이 실패해도 디스크에는 원래 요청이 남아 있으므로 다음 재실행에서 중복 실행 없이 확인합니다.

통신 오류/HTTP 5xx/429에서는 대기열이 있을 때만 5초부터 최대 60초까지 늘려 재시도합니다. 지속 점수 조회 polling은 없습니다. 앱이 백그라운드/종료된 동안 전송 성공을 보장하지 않으며 다시 전면으로 돌아왔을 때 재개합니다. 원래 전송 중이던 요청의 응답은 도착하면 저장할 수 있습니다.

읽을 수 없는 형식·다른 사용자 데이터·지원하지 않는 schema는 덮어쓰거나 초기화하지 않습니다. 공간 부족 시에도 기존 디스크 데이터를 남깁니다. 미전송 초안·대기 요청을 용량 확보 명목으로 자동 삭제하지 않습니다.

## 충돌과 종료

충돌은 해당 홀 전체 쓰기가 미반영된 상태입니다. 확인하면 확인한 score version과 새 mutation_id를 영속 저장한 뒤 재전송합니다. 그 사이 변경되면 다시 확인합니다. 거절은 충돌한 행만 최신 값으로 바꾸며 다른 직접 수정 값은 초안으로 보관합니다.

대상 목록이 달라졌다면 원래 요청을 보류합니다. 다시 준비할 때 현재 선택 대상과 제외될 플레이어를 보여 주고 확인합니다. 남아 있는 플레이어의 기존 score version을 유지하여 목록 변경을 틈타 새 서버 점수를 덮어쓰지 않습니다. 삭제 요청은 다시 준비한 초안에도 삭제 의도를 유지합니다.

서버가 `round_ended`를 반환하면 신규 입력을 잠그고 미반영 요청을 보관합니다. 이미 서버에 성공했던 요청의 중복 확인은 기존 idempotency 기록으로 처리합니다. 종료 이후 도착한 신규 오프라인 기록의 공식 처리 기준은 미확정이며 자동 유예·시간 소급·강제 덮어쓰기를 하지 않습니다.

## 범위와 남은 실기기 확인

- 처음 사용자 생성, 라운드 생성·참여, 아직 보관하지 않은 라운드 열기는 연결이 필요합니다. 골프장/플레이어 관리 전체를 오프라인 편집하는 단계는 아닙니다.
- 앱 삭제/데이터 삭제/새 기기에는 기기 초안이 자동 이전되지 않습니다. 서버에 성공적으로 전송된 기록은 기존 복구 수단으로 이어받습니다.
- 웹 UI 검증은 앱 코드가 로드 가능한 상태에서 API 통신을 차단하고 새로고침/탭 종료/재진입을 수행합니다. PWA 서비스 워커나 웹 앱 파일 자체의 최초 오프라인 로딩은 구현하지 않았습니다.
- Android 코드 번들에는 expo-network가 포함됩니다. 실제 비행기 모드, 통신 전환, OS 강제 종료, 재부팅, 저장 공간 부족, iOS/Android 뒤로가기/전면 복귀는 설치 빌드로 추가 확인해야 합니다.
- 라운드 종료 버튼/서버 자동 종료는 6단계, 받은 본인 기록의 종료+24시간 수정은 8단계에서 연결합니다.
