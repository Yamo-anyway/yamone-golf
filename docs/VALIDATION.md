- 앱 및 Worker TypeScript 타입 검사.
- Expo ESLint 검사.
- Worker/D1 API 통합 테스트 10개 + 앱 인증 보관/광고 정책 테스트 6개, 총 16개.
- 로컬 D1 `0001_identity.sql` 마이그레이션.

- 실제 Worker 코드를 Miniflare/D1으로 실행한 브라우저 UI 통합 흐름.

## 확인한 동작

1. 같은 닉네임으로 서로 다른 user_id와 개인 코드 발급.
2. 새로고침 후 같은 사용자로 복귀, 웹 인증 쿠키는 HttpOnly.
3. 닉네임을 변경해도 user_id와 개인 코드 유지.
4. 사용자 생성 요청을 동시에 6번 보내도 사용자 1명·활성 기기 1대.
5. 응답이 끊긴 등록 요청을 앱 재실행 후 동일 요청으로 재시도.
6. 기기 저장 실패 시 사용자 생성 요청 자체를 보내지 않음.
7. 복구 키로 동일 사용자 복구, 키 교체, 이전 기기 조회/변경 차단.
8. 동일 복구 키의 동시 사용에서 하나만 성공.
9. 복구 실패 시 기존 기기 유지.
10. 개인 코드·UUID로 인증 불가, DB에 인증 비밀값/복구 키 원문 미저장.
11. 웹 쿠키 변경 요청의 Origin 검사, 잘못된 입력과 반복 복구 시도 제한.
12. 광고의 앱 종료/장애 구분 및 ROUND 흐름 배너 제외, RECORD 흐름 배너 허용 규칙.
13. 한국어 및 일본어 기기→영어 기본값, 320px 영어 시작 화면 가로 넘침 없음.

화면 캡처는 `qa/stage-1/`에 있습니다. Linux QA 환경에는 한글 시스템 글꼴이 없어 캡처에만 Noto Sans KR을 주입했습니다. 실제 앱에는 QA 글꼴이나 테스트 사용자를 포함하지 않으며 기기 시스템 글꼴을 사용합니다.

## 검증 범위의 한계

- Android export는 APK 컴파일·설치 검증이 아닙니다. SecureStore의 휴대폰 재부팅·업데이트·삭제/재설치는 실기기에서 추가 확인해야 합니다.
- 실제 Cloudflare 계정, 운영 DB 생성/배포, 원격 Git push는 하지 않았습니다.
- `wrangler deploy --dry-run`은 자동 승인 검토에서 소스의 외부 전송 가능성을 이유로 차단되어 완료하지 않았습니다. 우회·재시도하지 않고 로컬 번들 및 Miniflare/D1 실행으로 확인했습니다.
- 이 실행 환경에서 `wrangler dev`는 네트워크 인터페이스 조회 오류로 시작하지 못했습니다. UI 검증은 같은 Worker 소스와 D1을 사용하는 격리된 Miniflare 서버로 수행했습니다. 해당 실행기는 `scripts/local-api.ts`와 `scripts/test-ui.ts`에 포함했습니다.
- 온라인 Expo 의존성 조회는 프록시 제한으로 실패했습니다. 설치된 SDK의 로컬 호환 목록 기준 검사와 실제 Web/Android export는 통과했습니다.
- 실제 광고 SDK/배너, Resend, 라운드 기능, 운영 백업 및 부하 검증은 후속 단계입니다.
