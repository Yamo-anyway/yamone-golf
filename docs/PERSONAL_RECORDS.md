# 8단계 개인 기록·통계·본인 수정 — v0.3.7

## 개인 목록과 통계

받은 기록은 골프장명 부분 검색과 전체/통계 대상/미완료/9홀 필터를 제공합니다. 20개씩 추가 조회하며 검색 조건을 유지합니다. 검색은 받은 기록만 대상으로 하고 받을 기록 목록에는 적용하지 않습니다. 슬롯 점수의 현재 합계와 입력 홀 수를 함께 표시합니다.

통계 조건은 RECEIPT received, 종료된 ROUND, 현재 Player Slot의 user_id가 수신자와 일치, 18홀, 본인 18개 홀 모두 숫자 점수인 경우입니다. 다른 플레이어의 미입력은 영향을 주지 않습니다. 9홀, 개인 삭제, 미수신, 현재 사용자 연결이 해제된 기록은 제외합니다. 신페리오 점수는 조회하지 않습니다.

평균/최저/최고는 실제 총 타수입니다. PAR 대비 평균은 각 라운드의 코스 Snapshot 합계 PAR를 뺀 값의 평균입니다. 공용 골프장 수정으로 과거 PAR가 바뀌지 않습니다. 홀 분포는 이글 이하(−2 이하), 버디(−1), 파, 보기(+1), 더블보기 이상(+2 이상)이며 해당 통계 라운드의 모든 18홀을 셉니다. PAR별 평균과 최근 10개 완료 라운드도 제공합니다. 통계가 없을 때 평균·최저·최고를 0으로 표시하지 않습니다.

제외 수는 현재 연결 해제 → 9홀 → 18홀 미완료 순서로 서로 겹치지 않게 분류합니다. 통계와 개인 목록의 완료 여부는 현재 원본 점수에서 서버가 계산합니다.

## 수정 권한과 고정 기한

현재 개인 기록을 가진 수신자 본인만 현재 연결된 자신의 Player Slot을 수정합니다. 라운드 생성자, 참여자, 기록자, 종료 위임 권한만으로 다른 선수 점수를 바꿀 수 없습니다. 비참여 수신자도 이 별도 API로 자신의 점수를 수정할 수 있으며 공동 라운드 입력 권한은 얻지 않습니다.

수정 가능 시간은 서버의 `rounds.ended_at + 86,400,000ms` 미만입니다. 정확히 24시간이 되는 순간부터 잠깁니다. 수신 시각, 다시 보내기/받기, 앱 시각, 마지막 점수 수정으로 연장하지 않습니다. 자동 종료도 서버에 저장된 실제 종료 기준 시각을 사용합니다.

실제 SQL 트랜잭션에서 활성 기기, received RECEIPT, 슬롯 연결/버전, 종료 상태, 홀 범위, 서버 시각, 점수 버전을 다시 확인합니다. 종료 후 연결 해제/재연결을 거쳤다면 같은 user_id라도 예전 슬롯 버전의 새 쓰기는 거절합니다. 쓰기 전에 이미 성공한 동일 요청을 조회하면 기한 만료·개인 삭제 이후에도 성공을 확인하되 새 점수를 쓰지는 않습니다.

## 점수와 원본

한 번에 본인 한 홀만 변경합니다. 입력 범위는 1~999 정수 또는 null이며 null/행 부재가 미입력입니다. 미입력 PAR는 기본 표시일 뿐 저장 전에는 통계/실제 점수가 아닙니다. 누락 홀 채우기와 자신의 홀 삭제도 같은 권한과 시간 제한을 사용합니다.

같은 값은 변경 없이 성공합니다. 다른 값이 최신 버전과 충돌하면 현재 값 → 수정값을 확인합니다. 확인 중 다시 바뀌면 다시 확인해야 합니다. 최신 값 적용은 충돌한 홀만 바꾸고 다른 홀 초안은 보존합니다.

저장은 같은 공동 원본 SCORE에 반영되어 다른 수신자도 새로 조회하면 변경된 전체 라운드와 순위를 봅니다. 사용자별 점수 복사본을 만들지 않습니다. 수정 이력은 score_audit, 요청 중복 방지는 score_mutations에 남깁니다. 라운드 record_version만 증가시키며 종료 시각과 자동 종료 활동 기준 updated_at은 변경하지 않습니다.

round_completions는 종료 당시 Snapshot으로 보존합니다. 종료 요약 화면은 현재 점수의 홀 수/합계를 사용하므로 수정 후 완료 여부와 실제 점수가 맞습니다. 향후 신페리오 실행 Snapshot은 이 수정 경로에서 바꾸지 않습니다.

## 수정 화면과 기기 저장

전반/후반, 홀 선택, PAR, 이 홀 저장/수정·취소·삭제, 본인 이름과 −/숫자/+ 구조입니다. 처음에는 첫 미입력 홀, 모두 입력됐다면 1번 홀에서 시작하고 이후 마지막 편집 위치를 복원합니다.

초안은 매 변경마다 사용자별 저장소에 먼저 씁니다. 화면/홀 이동 시 저장, 초안 보관, 저장하지 않고 이동, 계속 입력을 선택합니다. 여러 홀 초안이 남아 있으면 전체 초안을 버리는 것으로 오해할 수 있는 일괄 이동 동작은 제한하고 보관 이동을 제공합니다. 홈에서 수정 중인 기록으로 다시 들어갑니다.

저장 요청은 원래 mutation_id/user_id/receipt/slot/version/값을 기기에 먼저 보관합니다. 서버 결과를 모르는 요청은 다른 값으로 교체하거나 지우지 않습니다. 앱 재실행·통신 장애·응답 유실·서버 성공 후 기기 확인 저장 실패에서 같은 요청을 다시 확인합니다. 이전 요청 결과가 확정되기 전에는 다음 홀의 저장을 시작하지 않으며 다른 홀 초안은 보관할 수 있습니다.

광고는 없습니다. 초안/미확정 요청을 자동 전송하지 않습니다. 읽기 새로고침은 초안을 지우거나 버전을 몰래 바꾸지 않습니다. 서버가 기한 만료/연결 해제/개인 삭제를 알려 주면 입력을 잠그고 기존 값을 보관합니다. 확정 거절된 변경만 명시적으로 버릴 수 있습니다. 본인 수정은 진행 중 오프라인 대기열과 별도이며 기존 대기열을 자동 변환하거나 유예 시간을 추가하지 않습니다.

이 데이터는 앱 기기 저장소에 있으므로 앱 삭제로 사라진 미전송 초안은 복구 대상이 아닙니다. 서버 저장 성공을 확인한 뒤에는 최신 조회 전까지 추가 편집을 잠가 이전 점수 버전을 재사용하지 않습니다. 웹에서는 사용자별 Web Locks로 탭 간 저장을 직렬화합니다.

## 이번 단계의 범위

기존 0001~0006 마이그레이션을 그대로 사용합니다. 실제 광고 SDK/배너, 신페리오 계산, 이메일, 외부 Cloudflare 배포, 설치 APK/실기기 검증은 포함하지 않습니다. 기록 목록/통계는 온라인 조회이며 수정 초안 보관과 서버 확정은 구분합니다.
