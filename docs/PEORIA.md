# 신페리오 — 9단계 준비 v0.3.8

이번 변경은 이력 저장 구조와 읽기 API입니다. 계산 엔진, 실행/재계산 API, 앱 결과 화면은 아직 제공하지 않습니다. 계산 시간과 실행 권한은 개발 전달사항 31번에서 명시적으로 최종 확정이 필요하다고 한 항목입니다.

## 확정된 조건

- 종료 후 계산. 18홀 완주자만 포함하고 미완료자를 제외할 때 명시적으로 확인합니다.
- 최초 1회 + 재계산 2회 = 총 3개 결과. 과거 이력을 지우거나 덮어쓰지 않습니다.
- 숨김 홀은 각 계산에서 서버가 새로 무작위 선정하며 사용자 지정·공개는 없습니다.
- 계산 시각, 계산자, 대상/제외 선수, 당시 전체 점수, 결과/순위, 내부 숨김 홀을 보존합니다.
- 원본 점수 수정으로 과거 결과가 바뀌지 않습니다. 재계산을 명시적으로 실행해야 새 결과가 생깁니다.
- 신페리오 점수는 개인 골프 통계에서 제외합니다. 계산 자체에 전면 광고는 없습니다.

## 확정 요청을 위한 제안

| 항목             | 제안                                 | 적용 결과                                                               |
| ---------------- | ------------------------------------ | ----------------------------------------------------------------------- |
| 3시간의 시작점   | 서버의 라운드 종료 시각              | 최초와 재계산 모두 종료 후 3시간 미만에 실행. 재계산해도 기한 연장 없음 |
| 최초/재계산 권한 | 생성자와 종료 권한을 위임받은 참여자 | 동일 권한으로 두 동작 실행. 다른 참여자/수신자는 조회만 가능            |

이 표는 제안이며 코드의 확정 정책이 아닙니다. 시간 제한을 ‘최초 계산 후 3시간’으로 정한다면 최초 계산의 별도 마감 여부도 정해야 합니다. 제안대로 종료 기준을 선택하면 자동 종료의 경우에도 이미 확정된 서버 ended_at을 사용하며, 앱에서 종료를 확인한 시간이 기준이 되지는 않습니다.

사용자 점수 수정의 24시간과 신페리오 계산의 3시간은 독립입니다. 제안대로라면 종료 후 3시간 이후 본인 점수가 수정되더라도 과거 계산은 유지되고 재계산은 잠깁니다. 이는 시간 정책을 선택할 때 함께 고려할 동작입니다.

## 이번에 구현한 구조

`0007_peoria_history.sql`의 peoria_runs에 아래 값을 보관합니다.

- run_id / round_id / ordinal: 정수 순번 1~3, 라운드별 중복 금지.
- calculated_at / actor_id / actor_name: 당시 계산자와 이름 보존.
- source_record_version / algorithm_version: 입력 원본과 계산 방식 버전.
- snapshot_json: 당시 코스명, 18개 PAR, 전체 선수의 슬롯·연결 사용자·이름·18개 nullable 점수.
- target_slots_json / excluded_slots_json / results_json: 대상과 제외 구분, 총타수/핸디캡/네트 점수/순위.
- hidden_holes_json: 서버 내부 선정 홀. 조회 SQL에 포함하지 않습니다.
- request_id / request_hash: 향후 재시도의 중복 실행 방지에 사용할 공간. 아직 쓰기 API가 없으므로 재시도 동작도 미연결입니다.

공개 응답은 shared/peoria.ts에 정의했습니다. 저장 JSON을 그대로 내보내지 않고 중첩 항목까지 공개 필드만 새 객체로 구성합니다. 누락/잘못된 점수나 대상 구성이 발견되면 내부 데이터를 응답에 싣지 않고 peoria_history_invalid를 반환합니다.

라운드 참여자와 활성 개인 기록 수신자는 `GET /api/rounds/:id/peoria`로 조회합니다. 받은 기록 상세도 같은 공개 이력을 포함합니다. 권한과 이력을 한 D1 batch에서 조회하여 개인 기록 삭제 여부와 조회 데이터의 시점을 일치시킵니다. 최신 순번부터 반환하며 과거 원본 점수/이름을 현재 값으로 바꾸지 않습니다.

이 단계에는 이력 생성·수정·삭제 API가 없습니다. DB 관리자의 직접 SQL 변경을 막는 구조는 아니며, 최종 실행 API도 새 이력 INSERT만 사용하도록 연결해야 합니다. 테스트는 명시적으로 만든 이력을 격리 D1에 넣어 저장/조회 경계를 검증합니다. 이 테스트 수치는 실제 신페리오 계산 결과가 아닙니다.

## 정책 확정 뒤 연결할 실행 흐름

1. 서버에서 종료 상태·홀 수·권한·기한·현재 이력 수·최신 점수 버전을 조회합니다.
2. 앱에서 대상/제외 명단을 보여 주고, 재계산이면 새 추첨과 기존 결과 보존을 안내합니다.
3. 확인 뒤 서버가 최신 상태를 다시 검사합니다. 명단·점수·이력 수가 바뀌었다면 새 상태로 재확인을 받습니다.
4. 서버에서 난수로 숨김 홀을 선정하고 최신 점수 Snapshot으로 계산합니다. 기존 HTML의 mockPeoriaRun은 가짜 핸디캡이므로 재사용하지 않습니다. 계산식·반올림·홀 선정 규칙은 계산 방식 버전으로 명시하고 기준 예제와 검증합니다.
5. D1 쓰기 배치에서 활성 기기, 권한, 서버 기한, 원본 버전, 다음 순번을 재검사하고 Snapshot/결과/내부 추첨 정보를 하나의 새 행으로 저장합니다. 동시 계산으로 3개 제한을 넘거나 서로의 결과를 덮어쓰지 않아야 합니다.
6. 같은 실행 요청의 재시도는 기존 결과를 돌려줍니다. 응답 유실 때문에 새 추첨을 하거나 사용 횟수를 소모하지 않아야 합니다.
7. 최신 결과를 기본 표시하고 이전 결과 선택을 제공합니다. 원본과 계산 당시 버전이 다르면 변경 안내를 제공하되 자동 재계산하지 않습니다.

앱 신페리오 화면의 배너는 진입 흐름을 따릅니다. 종료 진행 흐름에서는 제외하고 개인 기록에서 일반 열람할 때만 다음 광고 단계에서 연결합니다.

## 기술 기준

D1 batch의 트랜잭션 및 실패 롤백 동작은 [Cloudflare 공식 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)를 확인했습니다. 기존 원본과 이번 조회 기반은 같은 D1 구조를 사용하며 외부 서비스나 새 라이브러리를 추가하지 않았습니다.
