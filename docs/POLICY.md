# 개발 기준 — 2026-09-23 최신 대화 반영

기존 전달사항과 충돌하면 이 문서의 최근 확정 사항을 우선 적용합니다. 일반 이메일 로그인은 도입하지 않습니다.

## 사용자와 기록

- 닉네임은 중복 가능하며 서버 user_id가 실제 식별자입니다.
- 한 사용자당 활성 기기 1대입니다. 복구 성공 시 새 기기만 활성화합니다.
- 개인 코드·QR은 다른 사용자와 연결하는 공개 정보, 복구 키는 비밀 정보입니다.
- 복구 수단이 없으면 관리자 검색 등 공식 복구 절차를 제공하지 않습니다.
- 이메일 이전·복구는 마지막에 연결합니다. 사용자 삭제 정책은 미확정입니다.
- 한국어 기기→한국어, 나머지→영어. 수동 설정은 system/ko/en입니다.
- USER / ROUND / PARTICIPANT / PLAYER SLOT / INPUT TARGET / SCORE / RECEIPT / DELIVERY / USER COURSE / PEORIA RUN을 분리합니다.
- 진행 중 라운드는 사용자당 하나이며, 플레이어 슬롯과 참여 사용자는 다른 개념입니다.
- 종료 후 미참여 플레이어가 받는 경우 해당 슬롯의 사용자 연결·전송·수신 관계로 처리하고, 진행 중 참여자를 추가한 것으로 취급하지 않습니다.
- 스코어는 null을 미입력으로 사용하고, 기본 PAR·작성 중·기기 보관·서버 저장을 구분합니다.
- 충돌 거절은 해당 항목의 최신 서버 점수로 전환하고 다른 초안은 보존합니다.
- 6시간 무갱신 서버 자동 종료와 플레이어별 9/18홀 완료는 별개입니다.
- 개인 통계는 본인 플레이어·수신 완료·18홀 완료 기록만 사용합니다. 신페리오·9홀은 제외합니다.
- 종료 후 수신자 본인의 점수만 종료 시각+24시간 안에 수정 가능합니다.
- 신페리오는 종료 후, 최초 포함 최대 결과 3개이며 과거 결과를 보존합니다. 3시간 기준점과 실행 권한은 미확정입니다.
- 자동 종료 후 지연된 오프라인 입력, 라운드 나가기 세부 조건도 구현 전에 확정합니다.

## 플레이어와 개인 입력 목록 — 3단계 반영

- 플레이어 연결은 해당 슬롯의 실제 사용자를 지정하는 작업입니다. 기록 참여자 추가나 광고 처리와 별개입니다.
- 개인 코드/QR을 조회한 뒤 닉네임과 개인 코드를 확인합니다. 동일 닉네임을 자동 병합하지 않습니다.
- 라운드 참여자는 진행 중 슬롯을 관리합니다. 7단계부터 종료 후에도 기존 참여자는 미등록 이름 수정·사용자 연결·해제를 할 수 있습니다. 슬롯 추가·삭제는 종료 후 허용하지 않습니다.
- 연결된 슬롯의 표시명은 사용자 닉네임입니다. 연결을 해제할 때 임시 이름을 지정하며 슬롯·스코어·입력 대상 연결을 유지합니다.
- 이미 스코어·전송·수신 참조가 있는 슬롯은 단순 삭제하지 않습니다. 현재 영향 안내와 삭제 차단을 제공하며 강제 삭제 정책은 만들지 않습니다.
- 안전한 삭제도 서버에서는 슬롯 ID와 변경 이력을 보존합니다. 영향을 받는 개인 입력 목록에서만 제거합니다.
- 내 입력 대상의 순서와 라운드 플레이어 순서·순위는 독립적입니다. 선택을 0명으로 저장하는 것도 허용합니다.
- 처음에는 전체 슬롯을 선택하고, 개인 목록을 저장한 뒤 추가되는 슬롯은 미선택으로 둡니다.
- 개인 선택·정렬만 바꾼 것은 공동 라운드의 기록 변화로 취급하지 않습니다.

## 전면 광고 — 사용자별 같은 라운드에서 1회 처리

1. 생성자는 생성 전에, 참여자는 참여 전에, 미참여 플레이어는 최초 기록 받기 전에 광고를 처리합니다.
2. 사전 기능 가능 여부 확인 → 광고 → 정상 완료 또는 장애 판정 → 서버 최신 권한·상태 확인 → 기능 실행 순서입니다.
3. 광고 없음·로딩 실패·표시 실패·로딩 시간 초과도 광고 처리가 끝난 것으로 인정합니다.
4. **광고 도중 앱 종료는 완료로 인정하지 않으며 기능을 실행하지 않습니다.** 재시도 시 다시 광고를 처리합니다.
5. 이미 광고 처리를 완료한 사용자에게 같은 라운드의 종료·기록 받기 등에서 광고를 다시 요구하지 않습니다.
6. 광고 뒤 서버 요청이 실패하면 광고 없이 기능만 재시도하며, 응답 유실은 서버 결과 조회와 요청 중복 방지로 처리합니다.
7. 광고 로딩 제한과 이미 표시 중인 광고의 닫힘 이벤트는 구분합니다.
8. 광고 완료와 기능 실행 사이 앱 종료는 처리 완료 증거와 보류 요청을 보관해 재실행 시 서버 상태 확인 후 이어갑니다.
9. 서버의 (user_id, round_id) 광고 처리 이력과 기능 요청 ID를 연결합니다. 생성 전에는 준비 요청 식별자가 필요합니다.
10. 광고 SDK·형식·운영 ID는 후속 연결 사항입니다. 현재 정책 함수가 광고 노출/완료를 증명하지는 않습니다.

배너는 콘텐츠와 함께 스크롤되지 않고 하단 탭/시스템 안전 영역 위에 고정합니다. 콘텐츠·버튼을 덮지 않아야 합니다. 배너 실패는 화면 사용을 막지 않고, 광고가 없을 때 빈 광고 칸을 유지하지 않습니다. 배너 노출은 전면 광고 1회 처리와 별개입니다.

## 홀별 입력 — 4단계 반영

PAR는 표시 기본값입니다. 저장을 누르기 전까지 미입력이고, 조정한 값은 저장 전 상태입니다. ‘이 홀 저장/수정’은 선택된 입력 대상 전체에 적용하며 미조정 PAR도 저장합니다. 다른 홀/화면으로 가는 동작은 변경이 있을 때만 3가지 선택을 표시합니다. 저장 실패/미확정 충돌은 이동을 막습니다.

서버는 점수 버전으로 최신 값을 확인합니다. 동일 목표 값은 아무 변경 없이 성공, 다른 최신 값은 전체 저장 보류와 확인입니다. 거절하면 충돌한 행만 최신 값으로 바꿉니다. 삭제는 선택된 대상의 이 홀만 null로 처리하고 버전은 남깁니다.

순위는 입력된 현재 합계의 오름차순이며 서로 다른 입력 홀 수도 함께 표시합니다. 동점은 1,1,3 방식의 공동 순위, 전부 미입력은 순위/합계 ‘—’입니다. 순위 정렬은 개인 입력 대상 순서를 변경하지 않습니다.

입력 범위는 1~999 정수이며 0은 입력 값이나 미입력으로 사용하지 않습니다. 5단계부터 앱 내 점수 초안은 사용자별로 기기에 영속 저장합니다.

## 오프라인과 기기 보관 — 5단계 반영

기기 초안, 전송 대기, 충돌 확인, 서버 반영 완료를 구분합니다. 모든 +/- 변경은 기기 저장이 성공한 뒤 화면에 반영합니다. ‘초안 보관 후 이동’은 서버 전송 의사가 아니며 자동 업로드하지 않습니다. ‘저장 후 이동’은 기기 대기열 기록이 성공했다면 통신 장애 중에도 이동할 수 있고 전송 대기임을 표시합니다. 저장 공간 오류나 확인되지 않은 충돌에서는 이동하지 않습니다.

아직 결과를 모르는 동일 홀 요청은 변경/삭제로 교체하지 않습니다. 결과 확인이 끝날 때까지 해당 홀 편집만 잠그고 다른 홀 입력은 허용합니다. 사용자·라운드·홀과 원래 요청 ID를 유지해 재전송합니다. 서버 반영 완료 응답과 로컬 대기열 갱신이 모두 끝나야 완료 상태가 됩니다.

종료 이후 늦은 오프라인 점수는 처리 기준 확정 전까지 보류하며 입력값을 보존합니다. 로컬 시각으로 종료 여부/수정 가능 시간/권한을 결정하지 않습니다. 앱 삭제·기기 저장소 삭제로 사라진 미전송 입력은 서버 데이터가 아니므로 복구 대상에 포함되지 않습니다.

## 종료 — 6단계 반영

생성자와 종료 권한을 위임받은 참여자만 공동 라운드를 종료합니다. 생성자만 위임/회수하며 실제 종료 쓰기 때 다시 검사합니다. 종료 전 모든 홀의 로컬 초안·전송·충돌을 확인합니다. 다른 기기에만 있는 오프라인 초안은 서버가 알 수 없으므로 동반자의 입력 여부를 함께 확인하도록 안내합니다.

마지막 공동 기록 변경 +6시간에 종료됩니다. 서버 Cron과 API 만료 검사로 관리하며 앱 실행에 의존하지 않습니다. 종료 상태와 Player Slot별 전체 9/18홀 완료 여부는 별도로 보존합니다. 모든 참여자의 진행 중 라운드 제한은 종료 트랜잭션에서 해제합니다. 다른 플레이어의 미완료가 내 완료 여부를 바꾸지 않습니다.

## 기록 보내기·받기 — 7단계 반영

전송 상태(pending/received/cancelled)와 개인 기록(received/deleted)을 분리합니다. 같은 라운드·슬롯·수신자의 대기 전송과 같은 사용자·라운드의 활성 개인 기록은 각각 하나입니다. 명시적으로 다시 보낼 때만 새로운 전송을 만듭니다.

개인 기록 삭제는 공동 원본과 이미 받은 전송 이력을 지우지 않습니다. 삭제한 기록은 과거 수신 요청 재시도나 홈의 최근 종료 목록으로 되살리지 않습니다. 새 전송을 받아도 같은 라운드 광고는 반복하지 않습니다.

받기는 전체 라운드 읽기 권한과 개인 목록 등록입니다. 다른 진행 중 라운드가 있어도 수신 가능하며 종료 라운드의 활성 참여자로 등록하지 않습니다. 종료 후 연결 해제 시 pending 전송은 취소하지만 이미 받은 개인 기록은 원래 수신자에게 남습니다.

수신 광고 중 전송 취소·연결 변경이 생기면 서버는 최신 상태를 검사해 수신을 거절합니다. 광고 처리가 완료됐다면 그 이력은 보존합니다. 앱 종료·응답 유실 후 원래 요청과 서버 결과를 확인하고, 삭제된 수신 결과는 다시 생성하지 않습니다.

## 개인 통계와 본인 수정 — 8단계 반영

개인 통계는 현재 본인 슬롯에 연결된 received 개인 기록의 완성된 18홀만 집계합니다. 9홀과 신페리오는 제외합니다. 다른 플레이어가 미완료여도 본인의 18홀 통계는 유지하며, 개인 삭제·본인 점수 null 변경·연결 해제는 다음 조회의 통계에 반영합니다.

수신자 본인만 현재 연결된 자신의 슬롯을 서버 종료 시각+24시간 미만에 수정합니다. 기한은 다시 수신하거나 수정해도 연장되지 않습니다. 동일 값은 변경 없이 처리하고 다른 최신 값은 버전 확인을 거칩니다. 원본은 하나이며 저장한 수정은 모든 수신자의 조회에 반영합니다. 종료 당시 완료 Snapshot과 신페리오 Snapshot은 수정하지 않습니다.

새로운 수정 요청은 기한 이후 거절하지만 이미 성공한 원래 요청의 재확인은 가능합니다. 초안·미확정 요청을 사용자별로 기기에 보관하고 자동 전송하지 않습니다. 진행 중 미전송 점수를 종료 후 수정으로 자동 변환하지 않습니다. 수정 화면은 배너 및 전면 광고 대상에서 제외합니다.
