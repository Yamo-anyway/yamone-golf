## 합친 내용

앱의 고정 스코어 입력, 방 생성·참여 흐름, 개인/라운드 QR 개선을 기존 개발 소스와 합쳤다. 관리자 0.3.22의 메뉴·국가 설정·목록/주소 표시·다국어·지역 분류·요청 관리·삭제/복구·GolfCore 수집을 원래 Worker 진입점에 연결했다. 공용 코스 API도 해당 버전의 국가 필터·표시 데이터·스냅샷 필드를 반영했다.

관리자 후속 ZIP에는 원래 TypeScript가 아닌 배포 번들이 있었다. 이를 모듈 경계별로 복구해 `src/*.recovered.js`에 보관했다. 해당 모듈은 공용 인증·SQL·오류 클래스를 기존 TypeScript 구현에서 가져오며, 독립된 두 번째 서버를 실행하지 않는다. 기존 `course-admin.ts`와 `course-admin-page.ts`는 복구 모듈의 명시적 진입점이다. 이름 직렬화가 필요한 관리자 페이지의 `__name` 처리를 보존했다. 공개 경계에는 타입 선언을 두었지만 복구된 JavaScript 전체가 엄격한 TypeScript 검사를 받는 것은 아니다. 향후 수정 시 해당 모듈의 동작 검사와 Worker 번들을 함께 확인한다.

## 데이터 보존과 마이그레이션

- `0010_course_catalog_operations.sql`: 누락된 코스 필드와 운영 관리 테이블을 추가한다.
- `0011_course_region_mappings.sql`: 공개 지역 분류 사전을 생성·보완한다.
- 빈 로컬 DB와 기존 0009까지의 DB에서 적용을 확인하며 사용자·골프장·즐겨찾기·라운드 Snapshot 보존 검사를 추가했다.
- ZIP의 `20261006_philippines_refresh.sql`, `20261007_admin_course_samples.sql`은 이 통합본에 넣지 않았다. 전체 운영 골프장 교체·샘플 초기화 SQL을 마이그레이션으로 취급하지 않는다.

**기존 운영 DB에 0010을 바로 적용하지 않는다.** 운영 0.3.22에서는 같은 필드/테이블이 이전 수동 SQL로 이미 만들어졌을 수 있다. 현재 운영 스키마와 `d1_migrations`를 읽고, 이미 존재하는 컬럼을 다시 추가하지 않도록 적용 이력을 대조해야 한다. 이는 작업 순서의 서버·운영 확인 단계에서 마무리한다. 이번에는 새 로컬 DB의 재현 가능한 기준만 확정했다.
