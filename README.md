# Yamone Golf v0.3.4 — Cloudflare 개발 5단계

오프라인 점수 입력, 여러 홀 초안, 앱 재실행 복구와 안전한 재전송을 추가한 개발판입니다. 기존 v0.2와 1~4단계 소스/태그를 보존합니다.

## 이번 단계에서 추가한 기능

- +/-로 점수를 바꿀 때마다 기기에 먼저 초안을 저장합니다. 저장이 성공한 뒤 화면의 값을 변경합니다. 여러 홀 초안과 마지막 홀 위치를 사용자·라운드별로 보관합니다.
- 홀/화면 이동에서 ‘저장 후 이동 / 초안 보관 후 이동 / 저장하지 않고 이동 / 계속 입력’을 제공합니다. 보관한 초안은 자동 전송하지 않습니다.
- ‘이 홀 저장/수정/삭제’를 누르면 정확한 요청 ID와 내용을 기기에 먼저 저장한 뒤 서버로 보냅니다. 통신이 끊겨도 대기열을 보존하며 서버 성공과 기기 저장을 구분합니다.
- 앱 재실행, 전면 복귀, 연결 복구와 명시적 재시도 시 전송합니다. 화면을 닫아도 앱이 전면에서 실행 중이면 전송을 이어갑니다. 일시 장애에는 대기열이 있을 때만 5~60초 간격으로 재시도합니다.
- 서버는 성공했지만 응답이 유실된 경우에도 같은 요청을 재전송합니다. 이후 다른 기록자가 바꾼 점수를 오래된 요청이 덮어쓰지 않습니다.
- 충돌한 홀은 확인 상태로 보관하고 다른 홀을 계속 입력/전송합니다. 재실행 후에도 확인 상태가 유지됩니다. 충돌 거절은 해당 행만 최신 값으로 바꾸고 다른 초안은 보존합니다.
- 입력 대상/플레이어 목록 변화는 보류합니다. 현재 선택과 제외될 플레이어를 확인한 뒤 다시 준비할 수 있습니다. 삭제 요청은 다시 준비해도 삭제 의도를 유지합니다.
- 종료된 라운드에 늦게 도착한 기록은 자동 적용하지 않고 기기에 보관합니다. 종료 이후 오프라인 점수 처리 정책은 미확정 상태입니다.
- 이전에 열어 보관한 점수 화면은 통신이 없어도 홈에서 다시 열 수 있습니다. 캐시된 사용자는 화면 복귀용이며 서버 인증/권한을 대신하지 않습니다. 모든 전송은 원래 user_id와 현재 인증 사용자가 일치해야 합니다.
- 웹에서는 탭 사이 저장을 잠가 여러 탭이 동시에 입력해도 로컬 데이터를 덮어쓰지 않게 했습니다. 손상된 데이터는 초기화하거나 덮어쓰지 않고 오류로 알립니다.

1~4단계의 인증/복구 키, 골프장, 생성/초대/참여, 플레이어/입력 대상, 점수 충돌·스코어카드·순위도 포함합니다. **광고는 개발 테스트 어댑터이며 실제 광고 SDK·배너는 아직 없습니다.** 이메일·Resend는 마지막에 연결합니다.

오프라인 사용을 위해 해당 기기에서 라운드 점수 화면을 한 번 열어야 합니다. 최초 사용자 생성/라운드 생성·참여에는 연결이 필요합니다. 앱 삭제나 기기 저장 데이터 삭제로 사라진 미전송 초안은 서버에서 복원할 수 없습니다. 웹 앱 자체의 최초 오프라인 로딩(PWA/서비스 워커)은 이번 범위가 아닙니다. 자세한 범위는 `docs/OFFLINE.md`에 정리했습니다.

라운드 종료/자동 종료는 다음 6단계이며, 현재 개발 라운드를 종료하는 UI는 없습니다. 종료 후 본인 점수 수정은 8단계입니다. 순서는 `docs/DEVELOPMENT.md`, 확정 기준은 `docs/POLICY.md`를 참고하세요.

## 기존 버전과 구분

- 기존 v0.2.0 원본 ZIP을 `baseline/`에 그대로 보존했습니다. `SHA256SUMS`로 확인할 수 있습니다.
- 앱 개발판 식별자는 `com.yamone.golf.dev`입니다. 기존 `com.yamone.golf`와 함께 설치할 수 있습니다.
- 새 D1 사용자는 기존 Node/SQLite 서버 사용자와 별개입니다. 이전 서버 데이터를 자동 이전하지 않습니다.
- 원격 Git 저장소·Cloudflare 계정에 업로드하거나 운영 DB를 생성한 상태가 아닙니다.

## 로컬 실행

Node.js 24와 npm을 사용합니다. 저장소 루트에서:

```bash
npm ci
npm run db:local
npm run server
```

별도 터미널에서 웹 확인:

```bash
npm run export:web
npm run preview
```

브라우저로 `http://localhost:4173`에 접속합니다. preview 서버가 `/api`를 로컬 Worker의 8787 포트로 전달합니다. preview는 개발 검증용이며 운영 호스팅 서버가 아닙니다.

휴대폰 실행 시 `.env.example`을 `.env`로 복사하고 `EXPO_PUBLIC_API_URL`을 **개발 컴퓨터의 LAN 주소와 8787 포트**로 설정합니다. 휴대폰의 localhost는 컴퓨터가 아닙니다.

```bash
cp .env.example .env
npm start
```

필요하면 Worker를 `npm run dev --workspace yamone-golf-cloudflare -- --ip 0.0.0.0`으로 실행하고 같은 네트워크의 휴대폰에서 접근합니다. QR 스캔과 네트워크 상태 감지는 새 개발 빌드에서 실기기 검증이 필요합니다. Web/Android export만으로 APK·실기기 검증이 끝난 것은 아닙니다.

## 검증 명령

```bash
npm run typecheck
npm run lint
npm test
npm run export:web
npm run export:android
```

UI 검증은 웹 export 후 아래 명령으로 실행합니다. 테스트가 별도 포트의 Worker/D1과 preview 서버를 자동 실행하고 종료합니다. 테스트 DB는 메모리에 격리되어 개발 DB를 변경하지 않습니다.

```bash
npx playwright install chromium
npm run test:ui
```

테스트에는 사용자·기기 복구, 라운드, 플레이어/입력 대상, 스코어, 오프라인 재실행·충돌·저장 실패·동시 탭 입력까지 포함됩니다.

특정 UI 검증만 실행하려면 `npm run test:ui -- tests/offline-ui.ts`를 사용합니다. 브라우저의 로컬 저장 잠금은 HTTPS 또는 localhost와 Web Locks 지원이 필요합니다.

설치된 Chromium을 사용할 때는 `PLAYWRIGHT_EXECUTABLE_PATH`로 실행 파일 경로를 지정할 수 있습니다.

## Cloudflare 연결

`yamone-golf-cloudflare/wrangler.jsonc`의 모든 0으로 된 DB ID는 로컬 개발용 자리표시자입니다. 배포 전 실제 개발·운영 D1 ID로 각각 교체해야 합니다. 구체적인 순서는 `docs/CLOUDFLARE.md`를 참고하세요.

현재 Cron은 만료된 요청 제한 데이터만 정리합니다. 6시간 라운드 자동 종료는 6단계에서 구현합니다.
